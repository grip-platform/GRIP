# Name Things So They Say What They Are

V>>, 2026-11-19, verbatim: "it makes it difficult for me to know which matter is which."

- When you create a folder, file, branch, matter or identifier, name it in plain words that say what it is, because the operator must tell things apart without opening them.
- When privacy requires a code on a shared surface (GRIP files, commits, pull requests, the mesh), keep the code there, because a plain name would carry the private matter onto that surface (`rules/personal-matters-stay-private.md`).
- When the same item lives in a private store, name its folder with the code followed by a plain slug, in lowercase, such as `m99-car-insurance-claim`, and keep the code alone as its key everywhere else, because the code keeps cross-references stable and the slug makes the item readable.
- When a slug would need a private person's name or a child's details, describe the matter instead, because git-crypt encrypts file contents but not folder or file names.
- When the subject itself is sensitive, such as family law, health or an allegation, ask the operator whether its folder carries a plain slug, a discreet one or the bare code, because the host can read a folder name.
- When you rename, update every live reference in the same change and leave signed records as they are, because a half-done rename breaks paths and a signed record's paths are evidence.

Narrative (origin, incidents, measurements): `docs/doctrine/clear-naming.md`.
