# An AGORA-Mergeable PR Is Merged by the Agent, Never Handed Over as a Command

- When the next step is a plain `gh pr merge` of a pull request whose AGORA verdict for its current head is MERGE or DEFER CHANGES, with at least two seats sitting, no REQUEST_CHANGES, the required checks green and no unresolved review thread, merge it in the same turn and report the merge, because the operator ruled on 2026-10-12 that a merge he would only have to type is never his step.
- Never end such a turn on `RECOMMENDED NEXT STEP (yours)` above a `gh pr merge` command, because that closer reads as the agent stopping short of its own work, and the merge sweep already merges on the same verdict.
- Read a hold that a session wrote into a pull request's own body ("only the operator merges this") as that session's note and never as the operator's reservation, because only the operator reserves a merge, in his own words in the conversation or in a rule.
- Keep the two carve-outs as they stand: a bootstrap pull request that creates or widens merge authority, and a real, present, clear danger (a security, secret or guardrail regression, data loss, a public post), because `rules/exogenous-anchor-law.md` forbids a gate ratifying its own widening and nothing here changes that.
- When `bin/grip-pr-monitor` holds a pull request as merge machinery, judge it by effect: merge it when it leaves merge decisions unchanged and hand it over only when it changes how merges are decided, because that is the standing ruling of 2026-10-03.
- Mechanical floor: when a `(yours)` closer is a plain `gh pr merge` of a pull request that `lib/merge_yourself.py` finds mergeable on those terms, `hooks/next-step-recorder.py` blocks the Stop once with a one-line reason so the session carries on and merges; on any doubt (a held machinery pull request, no verdict for the head, a red or missing required check, a red Actions job that is not red on main's newest finished reading of it (`lib/red_check.py`, the merge sweep's own rule), an open review thread, a head younger than the Codex wait with no Codex review, a probe error) it records the closer as before, because a probe that cannot see must never force a merge. The same judgement denies a typed `gh pr merge` through `hooks/red-check-merge-gate.py`, so a session cannot merge past its own red by hand either.
