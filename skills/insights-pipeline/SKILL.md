# Insights Pipeline

**Purpose:** Automated feedback loop that turns GRIP usage data into actionable improvements.

## Pipeline Stages

```text
0. REFRESH   → Re-run Claude Code /insights headlessly (grip-insights run): the facets Stage 8 reads
1. DETECT    → Scan metrics, MEMORY, KONO for recurring patterns
2. ANALYZE   → Evaluate which patterns warrant new skills
3. GENERATE  → Propose skill names, keywords, descriptions
4. RED-TEAM  → Run honest self-assessment of RSI loop quality
5. EXTRACT   → Pull actionable TODOs from red-team articles
6. EXECUTE   → Create GitHub issues for high-priority items
7. LEARN     → Record insights back to KONO memory
8. EVO       → Fractal facet calibration with GRIP context (evo.py)
```

## Quick Start

```bash
# Stage 0: refresh Claude Code's /insights facets and report (skipped while under 24 h old)
grip-insights run

# Full pipeline
python3 lib/auto_skill_generator.py report
python3 lib/red_team_reporter.py generate
python3 lib/redteam_todo_extractor.py extract

# Individual stages
python3 lib/auto_skill_generator.py detect      # Stage 1: Pattern detection
python3 lib/auto_skill_generator.py generate     # Stage 3: Skill proposals
python3 lib/red_team_reporter.py post            # Stage 4: Post as GitHub issue
python3 lib/redteam_todo_extractor.py sync       # Stage 5+6: TODOs + issues
Agent("/evo", run_in_background=true)            # Stage 8: Facet calibration — MUST be isolated Agent, never inline
```

## When to Run

| Trigger | Frequency | Why |
|---------|-----------|-----|
| RSI loop phase completion | Every phase | Course-correct early |
| After 5+ PRs merged | Weekly | Trend detection needs volume |
| User asks for `/insights` | On demand | Run `grip-insights run --force`; typing `/insights` in a GRIP session comes back hollow |
| Copilot workflow | Every 2 hours | Automated during active RSI |

## Pattern Sources

| Source | What It Detects | Threshold |
|--------|----------------|-----------|
| `learning/metrics.jsonl` | Skill usage gaps, mode transitions | 2x (YSH) |
| `MEMORY.md` TODOs | LEARNED items without skills | 1x (already validated) |
| `embeddings.db` (KONO) | High-recall memories | 2x recall count |
| Red-team articles | Concerns, RISK metrics | Any RISK/FAIL |

## Goodhart Protection

This pipeline is itself subject to Goodhart's Law. Guardrails:

1. **YSH threshold (2x)**: Patterns must recur 2+ times before they are proposed as skills, and a proposal becomes a skill only after a person reviews its issue (lowered from 3x on 2026-10-03)
2. **Max 3 issues per run**: Prevents issue flood
3. **File-path analysis**: Checks if work touches user-facing directories
4. **Score-chasing detection**: Flags many tiny PRs as gaming behavior
5. **Self-referential guard**: Alerts when loop only improves itself

## INS-0X Numbering

Each insight generated by this pipeline gets a sequential ID for cross-reference tracking:

- Format: `INS-01`, `INS-02`, ... (reset per session, global in MEMORY/TODO)
- Assign at Stage 1 (detect) — IDs persist through all 7 stages
- Reference in GitHub issues, MEMORY TODOs, and genome proposals: `(INS-03)`
- Insights that survive Stage 4 (red-team) are eligible for micro-skill genesis via `apply_genesis_proposals()`

## Genome Embodiment

Insights that pass red-team (Stage 4) become micro-skill proposals in the evolutionary genome:

1. Stage 4 (red-team) validates the insight is not self-referential noise
2. Surviving insights are passed to `apply_genesis_proposals()` in the converge Step 7 LLM review
3. The micro-skill enters the genome at fitness 0.5 with nursery protection
4. Over sessions, fitness evolves based on actual invocation — unused proposals decay naturally

This closes the loop: usage data → pattern detection → red-team validation → genome micro-skill → fitness evolution.

## Integration Points

- **Claude Code /insights (Stage 0)**: `bin/grip-insights` → `lib/cc_insights_refresh.py` runs
  `claude -p "/insights" --model claude-sonnet-5` from any harness and checks what it wrote:
  `usage-data/facets/` (read by Stage 8, `lib/evo.py`) and `usage-data/report.html` (read by
  `lib/insights_learner.py`). Exit 0 means sessions were analysed, 2 means partial, 1 means
  nothing usable. It spends the Claude weekly limit, so it skips while the report is under
  24 h old. Why not just type `/insights`: in a GRIP session it comes back hollow (the pinned
  `default` model alias is refused, and Opus 5.5 answers its small calls with nothing).
- **Startup hook**: `hooks/startup/output.sh` runs `skill_recommender.py banner`
- **Copilot workflow**: `data/copilot/workflows/insights-learning.yaml` (2-hour interval during RSI)
- **Red-team workflow**: `data/copilot/workflows/red-team-review.yaml` (weekly Friday)
- **KONO substrate**: Stores pattern insights as permanent memories
- **Converge Step 4**: Triggered when score delta > 15 (see converge SKILL.md)
